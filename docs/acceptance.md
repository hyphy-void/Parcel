# Parcel v0.1 验收记录

验收日期：2026-10-07，Asia/Shanghai。功能已经实现并部署到 Pi；本记录区分已执行的验证与尚未取得的外部设备结果。

## 环境与部署

- 主机：Pi4b，Linux ARM64，Ubuntu 内核 `6.8.0-1065-raspi`，约 8 GB 内存。
- 存储：SSD `/dev/sda2`，ext4 根分区，开始时约 96 GiB 可用；正式数据目录 `/srv/parcel`，要求挂载点 `/`。
- 工具链：Go 模块最低 1.26.0，固定构建工具链 1.26.8；Node 24.21.0，npm 11.19.0。
- 服务：专用 `parcel` 用户、systemd 已启用开机启动并运行；版本 `0.1.0`。二进制 `/opt/parcel/parcel`，配置 `/etc/parcel/parcel.env`。
- 访问地址：`http://192.168.5.16:8080`，只监听该 IPv4。UFW 仅新增 `192.168.5.0/24` 到 TCP 8080 的规则，保留原有 SSH 规则。
- 默认单文件 8 GiB、存储配额 20 GiB、物理磁盘保留 2 GiB；默认分享 24 小时、3 次下载资格。

## 真实 8 GiB 与混合负载

使用独立临时目录与回环端口，实写输入文件、上传文件和下载输出，不使用稀疏文件，也不操作正式数据。上传中与校验中分别 SIGKILL，恢复后发布；下载读取一段后重启服务，复用原票据通过 Range 取得剩余内容，完整 SHA-256 一致且仅计 1 次。

最终实测同时存在 **2 路上传、4 路下载、1 路校验**；Parcel 进程峰值 RSS 为 **50076 KiB（约 48.9 MiB）**，低于 256 MiB 门槛。上传含重启用时 162.249 秒，下载含重启与全量哈希用时 188.118 秒。重复完成、撤销清理及配额完全回收均通过。机器记录见 [acceptance-results.json](acceptance-results.json)。脚本采样的是 Parcel 进程 RSS，吞吐量来自同一 Pi 的 SSD 与回环网络，不能代表外部 Wi-Fi 客户端速度。

## 浏览器验收

Chromium 153、Firefox 155、移动端 Chromium（Pixel 7 模拟）分别执行以下 4 个场景，共 12 个：

1. 上传 → 密码解锁（包括错误密码）→ 原生下载（文件名和内容一致）→ 复用票据不重复扣次 → 撤销。
2. 内网 HTTP 剪贴板受限时，出现可手动复制的链接。
3. 创建上传回复丢失后刷新页面，找回原上传，不重复预留空间。
4. 20 MiB 分块上传在确认位置暂停/恢复；取消上传后延迟返回的旧请求不能恢复已取消状态。

最终发布构建的 12 个场景全部通过（约 3.7 分钟）。界面截图：[桌面接收页](previews/receive-desktop.png)、[手机分享页](previews/share-mobile.png)。网页不宣称原生下载已完成，保存进度由浏览器下载列表显示。
